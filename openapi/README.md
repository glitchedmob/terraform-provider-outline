# Outline API generation

## Pinned sources

`outline.openapi.json` is the unmodified `spec3.json` from [outline/openapi at `40f51b75efad84e3e860af3e1c8b5a58fd74bb48`](https://github.com/outline/openapi/tree/40f51b75efad84e3e860af3e1c8b5a58fd74bb48). The upstream commit is dated 2026-09-23. The file's SHA-256 is `71c211078aff5b950df1b478aed628a242df26fe94c3b5f055fef9b1d46f2731`. `LICENSE` is the original BSD-3-Clause license from that commit. This specification and code generated from it retain that license; provider code and the local overlay use the repository's MPL-2.0 license. Release archives include the upstream notice as `OUTLINE-OPENAPI-LICENSE`.

The IAM contracts target [Outline v1.10.1, commit `4a5a616a21be800257dc11cef4263d0dd0412156`](https://github.com/outline/outline/tree/4a5a616a21be800257dc11cef4263d0dd0412156) only. Compatibility with other releases is not claimed. Do not verify collection changes against `main`; its description and archive/delete APIs have changed since this release.

`oapi-codegen.yaml` selects 29 IAM operations:

- `auth.info`
- Users list, info, invite, update, update_role, suspend, activate, delete
- Groups list, info, create, update, delete, memberships, add_user, remove_user, update_user
- Collections list, info, create, update, delete, memberships, add_user, remove_user, group_memberships, add_group, remove_group

The original full specification is committed, but we generate only these operations and their model dependencies. The provider registers `outline_user`, `outline_group`, and `outline_collection` resources and data sources, plus the `outline_group_member` resource. Collection membership operations are generated for future grant resources; no direct user or group collection grants are currently managed. The new `usersUpdate` selection supports display-name changes using an explicit target UUID. API key creation/deletion require application sessions and are not generated. Passwords, token exchange, and magic-link authentication are outside this provider.

## Generation and drift checks

Run from the repository root:

```shell
make generate
make check-generated
```

`make generate` uses `go tool oapi-codegen` v2.8.0, pinned in `go.mod`, to apply `outline.overlay.yaml` with strict target matching and generate models and client methods in `internal/client/client.gen.go`. Nullable fields use `github.com/oapi-codegen/nullable` v1.2.0; the client runtime is v1.7.0. Generation reads only committed local specifications and overlay files. It never downloads a live specification. Go may download pinned tool dependencies on the first run.

Commit source, overlay, config, and generated output together. `make check-generated` regenerates and rejects tracked changes and untracked files under `internal/client/`. The Generated Client workflow runs this on pull requests and pushes to `main`. Unit tests also compare generation into a temporary file byte-for-byte and verify the upstream source checksum. When deliberately updating upstream, update the pin, checksum test, license, and this document after rechecking the server contracts.

## Calling conventions for resource authors

`internal/provider/apiClient` embeds `*client.ClientWithResponses` and uses the existing origin-restricted bearer transport, provider user agent, timeout, and redirect rejection. Provider Configure only builds this client; it does not call `auth.info` or any other endpoint.

Import `github.com/glitchedmob/terraform-provider-outline/internal/client`. Each RPC is a POST:

```go
response, err := api.UsersInfoWithResponse(ctx, client.UsersInfoJSONRequestBody{Id: userID})
```

`userID` is `github.com/google/uuid.UUID`, also aliased as `github.com/oapi-codegen/runtime/types.UUID`. Most ID fields use that type. GroupUser's returned id is a composite string, not a UUID. Required body fields are values; optional fields are pointers. Use the generated `...JSONRequestBody` type for calls, not a parallel handwritten request struct. Auth info has no body: `api.AuthInfoWithResponse(ctx)`.

Response wrappers expose `StatusCode()`, `HTTPResponse`, raw `Body`, `JSON200`, and documented `JSON400`/`JSON401`/`JSON403`/`JSON404`/`JSON429` variants. HTTP errors do not automatically become Go errors. Check status, the selected JSON variant, and required nested data before using it. Optional response fields stay pointers so missing data is detectable; decoding does not validate required fields or enum values. Use `.Valid()` on enums when validating input. Unknown statuses/content types retain raw Body. Read `Retry-After` from HTTPResponse on 429 responses. Generated wrappers do not retry requests or produce Terraform diagnostics. The resource and data source helpers add response validation and diagnostics; reuse those checks rather than handling only transport errors.

Key models are `User`, `Invite`, `Group`, `GroupUser`, `Collection`, `Membership`, `GroupMembership`, `PaginationResponse`, and `Auth`. Use `PermissionRead`, `PermissionReadWrite`, `PermissionAdmin` for collection grants; `GroupPermissionMember`/`GroupPermissionAdmin` for group membership; `UserRoleAdmin`/`UserRoleMember`/`UserRoleViewer`/`UserRoleGuest` for users. Collection defaults and direct grants are separate permissions.

Nullable fields have three states. A zero `nullable.Nullable[T]` omits the field, `nullable.NewNullNullable[T]()` writes JSON null, and `nullable.NewNullableWithValue(value)` writes a value. In particular, `CollectionsUpdateJSONRequestBody.Permission` must send null to make a collection private; omitting it preserves the current default and can trigger an unintended caller-admin grant in v1.10.1. The collection resource always sends the intended permission value or JSON null on create and update. Direct user/group grants use non-null `*Permission`.

List bodies use `*int` Limit/Offset. Responses return PaginationResponse with total and nextPath. The release middleware produces nextPath even for the last page. Advance offset using the returned page metadata and stop against total; do not rely on nextPath becoming empty or follow it through a different HTTP client. `checkResponse` and `checkEnvelope` validate status and success envelopes, redact the configured key from API diagnostics, and never retry writes. `nextOffset` rejects malformed and non-progressing pagination. The bearer transport waits on a context-aware five-requests-per-second limiter.

`walkGroups` rejects duplicate IDs and changing totals. It uses the release's default `updatedAt` ordering; concurrent changes can produce a diagnostic requiring a new lookup rather than an incomplete result. Group string validators count UTF-16 code units to match the release's Zod validators, including supplementary Unicode characters. The group data source checks all pages for exact, case-sensitive name matches and rejects ambiguous results. Group list memberships are only a preview. Use paginated `GroupsMembershipsWithResponse` for the full membership set. Admin `includeListOnly` can expose otherwise inaccessible collections but does not grant access to their contents.

In v1.10.1, omitting `users.list.filter` excludes suspended users, even for admins. Explicit `filter = all` includes pending, active, and suspended users for admins. `walkUsers` explicitly requests `filter = all`, orders by `createdAt ASC`, validates each returned user, and rejects duplicate IDs and changing totals. User email lookups compare exact lowercase, normalized emails across the complete list and reject ambiguity. Do not substitute an active-only list when checking email conflicts or proving absence.

Do not send X-Client-Version, which can change pagination totals, or X-Api-Version, which switches collection descriptions to rich-text presentation. The provider's default calls preserve the release's markdown description presentation.

### Group member resource contracts

The group membership contract is verified against `server/routes/api/groups/schema.ts`, `server/routes/api/groups/groups.ts`, `server/policies/group.ts`, `server/policies/utils.ts`, and `server/presenters/groupUser.ts`, and `server/presenters/user.ts` in the pinned v1.10.1 tree. Do not substitute behavior from `main` or infer ownership protection from another resource.

`outline_group_member` manages one group/user pair, not a group's entire membership set. Required `group_id` and `user_id` are canonical lowercase, nonzero UUIDs with `RequiresReplace`. Its computed stable Terraform ID and import format are `group_id/user_id`, with exactly one slash. The server presenter ID is `userId-groupId`; validate the returned pair but do not use that presenter ID as Terraform identity. The optional computed `permission` defaults to `member` and accepts only `member` or `admin`. An imported admin membership with omitted permission reconciles to `member`, rather than leaving the permission unmanaged.

Reuse `requireIAMAdmin` from the user helper for every operation, including reads and import refresh. This requires an active workspace admin. Resolve parents through the existing `readGroup` and `readUser` helpers, and use `managedGroup` to refuse externally linked or synchronized groups before membership reads or mutations. Do not copy the user resource's API-key-owner mutation restriction. Self-membership is supported because the release treats a workspace admin as a group admin regardless of their stored group permission. Membership operations do not change workspace roles. The pinned policies and handlers impose no last-group-admin or group-owner protection, and the resource does not add one.

Read and preflight through every page of `GroupsMembershipsWithResponse`. Group list memberships are previews, not a complete set. Validate page metadata, stable totals, duplicate pairs, and every returned item's group/user IDs, including consistency with its nested user and presenter ID. Group endpoints call `presentUser` without `includeDetails`, so both inline and listed users omit email even for admins. `validateGroupMemberUser` validates these public users separately; do not weaken `validateUser` or the parent account-read contract. Complete the walk even after finding the target pair, so later malformed pages cannot be ignored. Only a complete validated list can prove that pair absent. Missing parents must be established through `readGroup` or `readUser` and their release-verified checks. A membership endpoint's `403` or `404` is always an error, never evidence of absence; retain state on failed checks.

Create completes the parent checks and full membership preflight, rejects an existing pair with an import diagnostic, then calls `GroupsAddUserWithResponse` with explicit intended permission. The release's add handler is an upsert. A concurrent writer can insert the same pair between preflight and write, and the provider can overwrite that writer's permission. There is no atomic create-only API to close this race. Coordinate writers for a pair and document the limitation rather than claiming Create can prevent every adoption race.

Permission updates use `GroupsUpdateUserWithResponse` with explicit intended permission. Delete uses `GroupsRemoveUserWithResponse` for only the target pair. Validate mutation responses before replacing trusted state; never retry writes automatically. After successful create preflight, retain the trusted compound pair ID before attempting the write, not only after receiving a success response. Transport errors, failed envelopes, and malformed responses can follow a committed write and must preserve that recovery state. Terraform taints failed creates; users must inspect the actual membership, fix the error, and untaint an existing pair to reconcile it in place, or import it if state was lost. A retained pair ID alone does not prove that the write committed.

### Collection resource and lookup contracts

The collection contract is verified against `server/routes/api/collections/schema.ts`, `server/routes/api/collections/collections.ts`, `server/models/Collection.ts`, `server/models/Document.ts`, `server/policies/collection.ts`, and `server/presenters/collection.ts` in the pinned v1.10.1 tree. Deletion side effects also use `server/queues/processors/CollectionsProcessor.ts`, `server/queues/tasks/DetachDraftsFromCollectionTask.ts`, and `server/queues/tasks/CleanupDeletedDocumentsTask.ts`. The collection-grant migrations and `UserMembership`/`GroupMembership` models confirm that soft deletion retains direct and group collection-grant rows. Do not substitute later archive/delete or description behavior from `main`.

`outline_collection` manages an active collection by stable canonical lowercase, nonzero UUID. Short URL IDs, names, and full URLs are not import IDs. Name changes update in place. Names contain 1 to 100 Unicode code points, no URL, and no surrounding whitespace. The Collection ORM counts code points, unlike the group Zod limits. Duplicate collection names are valid, so Create does not adopt or deduplicate by name.

The resource manages only name, Markdown description, default permission, and sharing. Description defaults to an empty string and allows at most 100000 Unicode code points. The provider does not send `X-Api-Version`, preserving Markdown presentation; rich-editor edits can change the returned Markdown. Omitted or null permission means private, not unmanaged. Valid configured defaults are `read` and `read_write`; the resource rejects the server's `admin` default and archived collections during read, import, update, and delete. The lookup can read both. Sharing defaults to false, explicitly overriding the server's true creation default. Workspace sharing policies still apply. `allow_destroy` is a local false-by-default guard, not a server field, and import resets it to false. Match description, permission, and sharing before applying an imported resource or configuration defaults will change them.

`readCollection` reuses `requireIAMAdmin` for every UUID read, including refresh and import. Unlike users and groups, `collections.info` uses `rejectOnEmpty` before authorization. Only the decoded Outline `404 not_found` envelope with status 404 and `ok = false` proves absence. A 403 never proves absence, even after a complete admin workspace list. A foreign workspace's existing collection can return 403 and cannot appear in that list. Unexpected route/proxy 404 responses and malformed success bodies retain errors and state. Do not add the user/group enumeration fallback to this helper.

`walkCollections` verifies an active admin and requests `includeListOnly = true` with explicit `statusFilter = []`. In v1.10.1, an omitted status filter excludes archives, but the empty array includes active and archived collections. Admin `includeListOnly` includes private workspace collections without granting private-document access. Trash and other workspaces are excluded. Validate all pages, duplicate UUIDs, and stable totals. Name lookup requires an exact, case-sensitive match, rejects ambiguity across active and archived names, then reads the matching UUID and verifies the name has not changed. The data source returns null for private permission and an empty string for a null description; it does not summarize direct/group grants.

Creation unavoidably gives the caller direct collection-admin membership through the server's `AfterCreate` hook. The provider retains a usable returned UUID before validating the rest of the response. Create uses the generated raw request and generated response parser while retaining a valid JSON response body for identity-only recovery. A malformed setting that prevents full generated decoding does not discard a canonical returned UUID; no separate API response structs are used. Terraform taints failed creates; inspect the workspace, fix the error, and untaint an existing collection to reconcile in place, or import it if state was lost. A response without a usable UUID requires manual inspection before retrying because duplicate names are allowed.

Updates always supply the desired permission value or JSON null. The release handler compares permission to `read_write` before checking whether it was supplied. Omission can therefore create a caller-admin membership while preserving the stored default. Explicit values avoid this omission bug, but a real change from `read_write` to another default still creates that membership if the caller has no direct membership. An existing direct membership is not upgraded. These are server side effects, not provider-managed grants. Setting a private default does not remove existing direct or group access.

Deletion is blocked unless `allow_destroy = true` has been applied and stored before destruction. `collections.delete` soft-deletes the collection and trashes published, non-archived, non-template, non-trial documents through the default Document scope. Archived documents, templates, and trial-import documents remain. Drafts detach asynchronously. Direct and group collection-grant rows remain, and the workspace default-collection setting is cleared if it referenced the collection. Deleted documents become eligible for permanent cleanup after 30 days. Soft deletion is destructive, not a safe handoff or an immediate full purge, and the provider has no restore operation. The server refuses deletion of the last non-trashed workspace collection. A failed delete response, including 403 or 404, retains state; only a later verified info read can establish absence.

Future collection user/group grant resources must reuse `readCollection`, `requireIAMAdmin`, and `walkCollections` where needed. They must verify their own membership-endpoint absence and authorization contracts rather than treating an empty workspace list, a grant-endpoint 403/404, or admin metadata access as proof of absence or document access. Collection defaults and direct grants need separate lifecycle rules.

## IAM behavior and limits

Use an unrestricted admin-owned Outline API key for these IAM operations. User, group member, and collection operations verify that the caller is an active admin. All user modifying actions reject the key owner's UUID or normalized email before a write; group member operations support the key owner's membership. Endpoint-scoped keys and server policies can still reject calls. OIDC provisioning uses invitations with `suppressEmail` and separate SSO configuration, not passwords or magic-link sign-in.

The release inviter ignores existing accounts, reports them in `unsent`, and returns only new users. Create checks the full admin user list first and still rejects `unsent` to handle races. Existing users are never adopted or modified during Create; import their UUID instead. Guest invitations become member invitations in v1.10.1, so the resource reads the stored role and reconciles it. The supported API roles `admin`, `member`, `viewer`, and `guest` are tested on this release. Editions and licenses may restrict roles; the provider reports server errors or a response that fails to confirm the intended role.

The user resource requires an explicit final `suspended` boolean. A role change on a suspended account temporarily activates it, changes the role, then restores the requested final state. If a follow-up write fails and that state is suspended, it makes a best-effort attempt to suspend again. Activation is not a sign-in or proof that an IdP account can authenticate.

User creation retains a newly returned matching UUID in state before follow-up validation, reads, and writes. Terraform taints failed creates. After fixing the error, untaint to reconcile in place; if state was lost, inspect the workspace and import the account's UUID. Default destruction only suspends the account, retains its memberships and content, and removes Terraform state. Recreating the same email refuses the retained account and requires import. Opt-in `delete_permanently` calls `users.delete`, which is irreversible through this provider. The released server anonymizes and soft-deletes users; this does not guarantee a full purge or delete their documents.

User email is required and immutable. Invitations use lowercase, normalized email while state preserves equivalent configured casing. Configuration changes require replacement, not renaming; Outline's confirmation flow must run outside the provider. The optional computed name has no default. Omission uses `Pending user` on creation and leaves the name unmanaged afterward. The released User ORM validates name length by Unicode code points, unlike group Zod limits, and rejects names containing its `NotContainsUrl` pattern. Configured names are reapplied if IdP sign-in changes them. Role defaults to member, `suppress_email` defaults to true and is creation-only, and `delete_permanently` defaults to false. See the [OIDC guide](../docs/guides/oidc.md) for replacement, import, and recovery procedures.

Group description requires an update after creation in this release; the group resource performs that follow-up update. It persists the returned ID before the second write. A failed create still taints the resource in Terraform; untaint after fixing the error to recover with an in-place update. Group update cannot clear externalId with null, and externally synchronized groups reject manual name/membership changes. The resource rejects externally synchronized groups and exposes no external_id argument. The data source can read an externally synchronized group by UUID. The group member resource also refuses these groups, including during reads and import. Collection creation defaults `templateManagement` to admin at the server. The collection resource leaves that setting, sort, commenting, color, icon, and document content outside its schema. It explicitly manages sharing and default permission as described above.

The group resource implements UUID import, in-place updates, refresh, and deletion for manually maintained groups. The v1.10.1 `groups.info` handler authorizes a nil model, producing `403 authorization_error` for nonexistent IDs. `readGroup` does not equate 403 or an unexpected route/proxy 404 with absence. It requires `auth.info` to confirm an admin and `walkGroups` to complete an unfiltered workspace list with consistent pagination totals. A listed ID, failed check, or malformed page preserves the error and state. Its data source requires exactly one configured UUID or name and returns description and mention settings.

The missing-user contract was independently verified against v1.10.1. `users.info` also authorizes a nil model and returns `403 authorization_error` for a nonexistent UUID. `readUser` only treats this response as absence after verifying an active admin and completing the full `filter = all` workspace user list, including suspended accounts. A bare 403 is never absence. An unexpected `users.info` 404 also requires the complete list check, since a missing route or proxy response does not prove the account was deleted. A listed UUID or failed verification preserves the error and resource state. The user data source requires exactly one UUID or email and returns the current name, role, and suspension state. Future resources must verify their own missing-object contracts rather than copy either fallback blindly. The group member resource reuses these parent helpers but never treats membership endpoint errors as absence. Future collection grant resources must keep the collection absence contract separate from grant-endpoint behavior, as described above.

Contract and provider unit tests use local HTTP fixtures. `make testacc` exercises group behavior, user admin API provisioning, group membership lifecycle, and collection access/deletion behavior against a disposable Docker stack pinned to Outline 1.10.1. The test-only bootstrap uses that released image's ORM hooks to create an admin and unrestricted API key in an empty database; it does not use ambient Outline credentials or add API-key endpoints to the generated client. User provisioning and pending-user membership tests run without SMTP, passwords, or sign-in. They include no fake IdP and make no OIDC-handshake, token-exchange, first-sign-in, or identity-linking acceptance claim. See [acceptance test setup](../README.md#acceptance-tests) for requirements, isolation, and cleanup.
