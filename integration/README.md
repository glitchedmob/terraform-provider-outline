# Acceptance fixtures

These scripts run only inside disposable Compose stacks. Default `compose.yml` disables rate limiting for large pagination fixtures. `TestAccRateLimitRealMiddleware` explicitly adds `compose.rate-limit.yml`, which pins Outline 1.10.1 and enables the released limiter with multiplier 1, default 1000-request capacity, and a 60-second default window. No ambient production limiter settings select this mode.

## Rate-limit source audit

The audit uses Outline commit [`4a5a616a21be800257dc11cef4263d0dd0412156`](https://github.com/outline/outline/tree/4a5a616a21be800257dc11cef4263d0dd0412156), not `main`. The compiled modules and `rate-limiter-flexible` 2.4.2 library in the released image were also inspected.

- [`server/middlewares/rateLimiter.ts`](https://github.com/outline/outline/blob/4a5a616a21be800257dc11cef4263d0dd0412156/server/middlewares/rateLimiter.ts) consumes IP then credential quota for API keys. Registered routes consume `${fullPath}:${identifier}`. Consumption rejects before `next()`, sets the four quota headers, and throws `RateLimitExceededError`. A route's first request registers and consumes its route bucket too.
- [`server/utils/RateLimiter.ts`](https://github.com/outline/outline/blob/4a5a616a21be800257dc11cef4263d0dd0412156/server/utils/RateLimiter.ts) normalizes paths, derives a SHA-256 credential identifier, sets the `rl` Redis prefix, and defines the quota strategies. The fixture calls these released helpers and reads the released credential prefix. [`server/models/ApiKey.ts`](https://github.com/outline/outline/blob/4a5a616a21be800257dc11cef4263d0dd0412156/server/models/ApiKey.ts) and [`server/utils/crypto.ts`](https://github.com/outline/outline/blob/4a5a616a21be800257dc11cef4263d0dd0412156/server/utils/crypto.ts) store the same SHA-256 of the token used by `RateLimiter.hashToken`. The fixture can therefore derive the credential identifier from the stored key hash without receiving or persisting plaintext credentials. It does not guess Redis storage layout.
- The pinned [groups](https://github.com/outline/outline/blob/4a5a616a21be800257dc11cef4263d0dd0412156/server/routes/api/groups/groups.ts), [users](https://github.com/outline/outline/blob/4a5a616a21be800257dc11cef4263d0dd0412156/server/routes/api/users/users.ts), and [collections](https://github.com/outline/outline/blob/4a5a616a21be800257dc11cef4263d0dd0412156/server/routes/api/collections/collections.ts) route definitions select 10/minute, 50/hour, 10/hour, and 100/hour respectively. Their limiter precedes resource validation, transaction, and mutation. `collections.add_user` authenticates first, so activity timestamps can change even when the grant is rejected.
- In the image's `node_modules/rate-limiter-flexible/lib/RateLimiterStoreAbstract.js`, `set(key, points, seconds)` prefixes the key and calls `_block`. `RateLimiterRedis.js` writes those consumed points with an expiry; subsequent `consume()` increments that same Redis key and reads its TTL. `_afterConsume` rejects when consumed points exceed the configured limit. This lets the fixture exhaust a real bucket without issuing dozens of mutating requests.
- [Error serialization and the runtime contract](../openapi/README.md#verified-pre-mutation-rate-limit-retries) establish the exact public four-field error envelope and rounded-up `Retry-After`/`RateLimit-Reset` seconds.

`rate-limit-fixture.cjs` refuses another version, disabled or multiplied limits, non-test database/Redis endpoints, a non-loopback test URL, or another application secret. It requires exactly the bootstrap team, admin, and unrestricted key, with no other users or keys. It supports only inspection and exhaust/clear actions on the four audited routes. It finds the ephemeral key's hash in the database, never accepts a key in command arguments, and emits no key, hash, bucket identifier, or Redis URL. It changes only that key's selected route bucket, not an IP bucket, global quota, or middleware implementation.

## Live coverage and boundary

The eleven-group batch does not use quota setup. Eleven real Terraform creates naturally exhaust the ten-per-minute bucket. A pass-through HTTP observer forwards unmodified requests and preserves responses; it neither synthesizes a 429 nor changes headers or delays. The batch must observe exactly one real rejection, complete with eleven distinct untainted UUIDs, produce an empty next plan with stable state, and leave no state or remote groups after destroy. Containers and volumes are also removed through registered stack cleanup.

For zero-budget and hourly-budget cases, the guarded script sets a fully consumed credential bucket with the route's real window. Each call then reaches the released Redis-backed middleware and must receive its actual 429. A zero budget exposes the rejection without retry. A 120-second budget rejects an hourly delay immediately without replay. The quota table and live headers check multiplier-1 limits for all four routes. Bootstrap counts remain unchanged, and each fixture bucket is cleared afterward.

Hourly tests cover `users.invite`, `collections.add_user`, and `users.delete` rejection handling. The invitation is otherwise valid; grant and deletion requests use non-existent target UUIDs so a broken fixture cannot alter a real account or grant. These do not prove natural hourly exhaustion, successful hour-long retries, or a full hourly Terraform apply. Local HTTP tests cover partial Terraform state, retries, and cancellation; the pinned source audit establishes the pre-mutation ordering.

The observer logs only the five allowlisted response headers and the public error body after checking their exact contract. Arbitrary error output is withheld. General acceptance artifacts may still contain the disposable API key through Terraform configuration, so keep them private.
